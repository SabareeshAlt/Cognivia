1. PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AcademeRAG is a full-stack AI-powered academic assistant that uses 
Retrieval-Augmented Generation (RAG) technology to answer questions based on 
uploaded academic documents (PDFs). The system combines:

  • A Django REST API backend for handling requests
  • A modern React (TypeScript) frontend with a chat interface
  • Milvus vector database for semantic document search
  • Ollama for local LLM inference (using Llama models)
  • LangChain framework for RAG pipeline orchestration

The application allows users to ask questions about academic content, and the 
AI retrieves relevant information from the indexed PDFs to provide accurate, 
context-aware answers with source citations.

5. HOW RAG (RETRIEVAL-AUGMENTED GENERATION) WORKS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DOCUMENT INDEXING (One-time setup):
  1. PDF documents are loaded from the project folder
  2. Text is extracted from each page using PyPDF
  3. Text is split into chunks (800 characters each)
  4. Each chunk is converted to a vector embedding using mxbai-embed-large
  5. Embeddings are stored in Milvus vector database (collection: "AcademeRAG")

QUERY PROCESSING (Every question):
  1. User submits a question via the chat interface
  2. Question is converted to a vector embedding
  3. Milvus performs similarity search to find top-5 relevant chunks
  4. Retrieved chunks are combined as "context"
  5. Context + question are sent to Llama 3.2 LLM
  6. LLM generates an answer grounded in the retrieved context
  7. Answer is returned to the frontend and displayed

FLOW DIAGRAM:
  User Question → Embed → Vector Search → Retrieve Context → LLM → Answer
                         (Milvus DB)        (Top 5 chunks)   (Llama 3.2)

7. HOW TO RUN THE PROJECT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PREREQUISITES:
  1. Python 3.9 or higher installed
  2. Node.js 18+ and npm installed
  3. Ollama installed and running (https://ollama.ai)
  4. Required Ollama models pulled:
     - ollama pull llama3.2
     - ollama pull mxbai-embed-large

STEP 1: Start Ollama
  $ ollama serve

STEP 2: Start Django Backend (Terminal 1)
  $ cd "/Users/apple/Applications/Visual Studio Code/Project"
  $ source venv/bin/activate
  $ python manage.py runserver 8000

STEP 3: Start React Frontend (Terminal 2)
  $ cd "/Users/apple/Applications/Visual Studio Code/Project/Frontend"
  $ npm run dev

STEP 4: Access the Application
  • Frontend: http://localhost:8080
  • Backend API: http://localhost:8000/api/

8. KEY FEATURES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ Knowledge-Grounded Responses
  AI answers are based on actual content from uploaded academic documents,
  reducing hallucinations and improving accuracy.

✓ Local LLM (Privacy-Focused)
  Uses Ollama for local inference - no data sent to external APIs.
  Complete privacy for sensitive academic materials.

✓ Semantic Search
  Milvus vector database enables intelligent retrieval of relevant content
  based on meaning, not just keyword matching.

✓ Modern Chat Interface
  React-based UI with smooth scrolling, loading states, and responsive design.
  Dark theme with professional styling.

✓ Multiple Frontend Options
  - React/TypeScript (primary) - Full-featured modern interface
  - Final.html - Standalone HTML (no build required)
  - Gradio.py - Quick Python-based UI for testing

✓ RESTful API
  Clean Django REST API that can be integrated with any frontend or service.

✓ Health Monitoring
  Built-in health check endpoint to monitor system component status.

AcademeRAG is a sophisticated, full-stack academic assistant that combines:
  • A Django REST API backend
  • A React TypeScript frontend
  • Milvus vector database for semantic search
  • Ollama for local, private LLM inference
  • LangChain for RAG pipeline management

The system allows users to upload academic PDFs, which are automatically
indexed into a vector database. Users can then ask natural language questions
and receive accurate, contextually-grounded answers with source references.

This is a privacy-focused solution that runs entirely locally, making it ideal
for handling sensitive academic or organizational documents without sending
data to external cloud services.
